# 프로세스와 스레드 소개

> 자바 고급1편 | DEEP

## 전체 흐름 한눈에 보기

```
CPU 1개로 프로그램 여러 개를 동시에?
  → 멀티태스킹: 시분할(Time Sharing)로 아주 빠르게 교차 실행 → 동시처럼 보임

프로세스 vs 스레드
  → 프로세스: 실행 중인 프로그램 전체 (독립된 메모리)
  → 스레드: 프로세스 안에서 실제 실행 단위 (메모리 공유)

단일 스레드 → 멀티 스레드
  → 문제: 한 작업이 오래 걸리면 다음 작업이 블로킹됨
  → 멀티 스레드로 병렬 처리 가능 → 동시성 문제 발생
  
→ 이후 챕터에서 동시성 문제를 하나씩 해결
```

---

## 멀티태스킹과 시분할

CPU 코어가 1개인 컴퓨터에서 음악을 들으면서 문서 작업을 하는 것을 어떻게 동시에 할 수 있을까?

비결은 **착각**이다. CPU가 프로그램A를 0.01초 실행하다가 멈추고, 프로그램B를 0.01초 실행하다가 다시 프로그램A로 돌아오는 식으로 아주 빠르게 교차한다. 사람은 이 속도를 인지하지 못하기 때문에 동시에 실행되는 것처럼 느낀다.

이를 **시분할(Time Sharing)** 기법이라 하며, 여러 프로그램을 동시에 실행하는 능력을 **멀티태스킹**이라 한다.

CPU를 어떤 프로그램에 얼마나 배분할지는 **운영체제의 스케줄러**가 결정한다.

CPU 코어가 여러 개라면? → **멀티프로세싱**. 여러 코어가 각각 다른 프로그램을 물리적으로 동시에 실행할 수 있다.

---

## 프로세스 vs 스레드

**프로세스**: 실행 중인 프로그램 하나. 운영체제로부터 독립된 메모리 공간(코드, 데이터, 힙, 스택)을 할당받는다.
- 프로세스끼리는 메모리를 공유하지 않는다 → 서로 영향을 주기 어려움 (안정적)

**스레드**: 프로세스 안에서 실제로 실행되는 흐름 단위. 하나의 프로세스는 최소 1개의 스레드(메인 스레드)를 가진다.
- 같은 프로세스의 스레드들은 **힙 메모리를 공유**한다 → 효율적이지만 동시성 문제 발생 가능
- 각 스레드는 자신만의 **스택(Stack)**을 가진다 → 지역변수, 메서드 호출 정보는 독립적

```
프로세스 A
├── 스레드1 (main)  [스택: 독립]
├── 스레드2         [스택: 독립]
└── 힙 메모리 (공유) ← 동시성 문제의 근원
```

## 멀티스레드가 필요한 이유

단일 스레드로 "파일 다운로드 + 화면 렌더링"을 하면, 다운로드가 끝날 때까지 화면이 멈춘다.  
멀티스레드를 쓰면 두 작업을 병렬로 처리할 수 있다.

하지만 여러 스레드가 같은 힙 메모리를 공유하면 **동시성 문제**가 발생한다.  
이것이 이후 챕터들에서 계속 다루는 핵심 주제다.

---

## 컨텍스트 스위칭

CPU가 스레드A에서 스레드B로 전환할 때, 현재 스레드A의 실행 상태(레지스터 값, 프로그램 카운터 등)를 저장하고, 스레드B의 이전 상태를 복원하는 작업.

이 작업 자체도 비용이 든다. 스레드가 너무 많으면 컨텍스트 스위칭 오버헤드로 오히려 느려질 수 있다.

## 면접 Q&A

**Q: 프로세스와 스레드의 차이는?**  
A: 프로세스는 실행 중인 프로그램으로 독립된 메모리 공간을 가진다. 스레드는 프로세스 안의 실행 단위로, 같은 프로세스의 스레드끼리는 힙 메모리를 공유하고 스택만 독립적으로 가진다.

**Q: 멀티프로세싱과 멀티스레딩의 차이는?**  
A: 멀티프로세싱은 여러 프로세스를 동시에 실행하는 것으로, 프로세스 간 메모리는 격리된다. 멀티스레딩은 하나의 프로세스 안에서 여러 스레드가 실행되는 것으로, 메모리를 공유해 효율적이지만 동시성 문제가 생길 수 있다.

**Q: 컨텍스트 스위칭이란?**  
A: CPU가 실행 중인 스레드를 바꿀 때, 현재 스레드의 실행 상태를 저장하고 다음 스레드의 상태를 복원하는 과정. 이 자체에도 비용이 들어, 스레드가 너무 많으면 전환 비용이 성능을 오히려 저하시킬 수 있다.
