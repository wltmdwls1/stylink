# 스프링 AOP 개념

> Spring 고급편 | ADV

---

## 전체 흐름 한눈에 보기

```
핵심 기능 (Core Concerns): 비즈니스 로직 (OrderService.order())
부가 기능 (Cross-cutting Concerns): 로그, 트랜잭션 등
  → 수십 클래스에 반복 적용 필요 → 수정 시 전체 파일 수정
  ↓
애스펙트 (Aspect): 부가 기능 + 어디에 적용할지를 하나로 모듈화
  @Aspect = Advice(부가 기능) + Pointcut(어디에)
  ↓
AOP 적용 방식 3가지:
  컴파일 타임 위빙: AspectJ 컴파일러 필요 (복잡)
  클래스 로드 타임 위빙: -javaagent 옵션 필요 (번거로움)
  런타임 위빙 (프록시): 스프링 AOP 방식 ← 표준
  ↓
스프링 AOP 제약: 조인 포인트 = 메서드 실행만 (프록시 기반)
```

---

## 핵심 기능 vs 부가 기능

| | 핵심 기능 | 부가 기능 |
|---|---|---|
| 정의 | 해당 객체가 제공하는 고유 기능 | 핵심 기능을 보조하기 위한 기능 |
| 예시 | 주문 처리, 재고 관리 | 로그 추적, 트랜잭션 |
| 특징 | 독립적으로 존재 | 핵심 기능 없이 단독 사용 불가 |

부가 기능의 문제:
```
부가 기능 적용 대상 100개 → 100곳에 코드 추가 필요
부가 기능 수정 시       → 100곳 파일 수정 필요
부가 기능 적용 위치 변경 → 또 100곳 수정 필요
→ 이것이 횡단 관심사(cross-cutting concerns) 문제
```

---

## 애스펙트 (Aspect)

```
부가 기능 로직 + 어디에 적용할지 선택 = 하나로 정의 → 애스펙트(Aspect)
```

**@Aspect가 바로 애스펙트다.**

```
Advisor (스프링 AOP 전용) = Advice + Pointcut → 이것도 하나의 애스펙트
```

> 애스펙트는 "관점"이라는 뜻. 애플리케이션을 "기능 하나하나"가 아닌 "횡단 관심사" 관점으로 바라보는 것.  
> **AOP(Aspect-Oriented Programming)** = 이 애스펙트를 사용한 프로그래밍 방식

**스프링 AOP는 OOP를 대체하지 않는다.** 횡단 관심사를 깔끔하게 처리하기 위해 OOP를 보완하는 기술이다.

## AOP 적용 방식 3가지

### 1. 컴파일 타임 위빙

```
.java 소스 코드 → (AspectJ 컴파일러) → .class (이미 부가 기능 코드 포함)
```

- AspectJ 전용 컴파일러 필요
- 컴파일된 `.class` 보면 이미 애스펙트 호출 코드가 삽입됨
- **단점**: 특별한 컴파일러, 설정 복잡

### 2. 클래스 로드 타임 위빙

```
.class → (JVM 클래스 로더 조작기) → JVM (부가 기능 코드 추가된 상태로 로드)
```

- Java Instrumentation 활용
- **단점**: 자바 실행 시 `-javaagent` 옵션으로 클래스 로더 조작기 설치 필요 → 운영 복잡

### 3. 런타임 위빙 (스프링 AOP 방식)

```
실제 대상 코드는 그대로 → 프록시를 통해 부가 기능 적용
항상 프록시를 거쳐야 부가 기능 사용 가능
```

- 특별한 컴파일러, JVM 옵션 없이 스프링만으로 사용 가능
- **단점**: 메서드 실행 지점에만 AOP 적용 가능 (프록시 한계)

| 방식 | 원본 코드 변경 | 도구 |
|------|--------------|------|
| 컴파일 타임 | 변경됨 (코드에 삽입) | AspectJ 컴파일러 |
| 클래스 로드 타임 | 변경됨 (바이트코드 조작) | -javaagent |
| **런타임 (프록시)** | **변경 안 됨** | **스프링 AOP** |

## AOP 적용 위치 (Join Point)

AOP를 적용할 수 있는 위치들:

| 위치 | 설명 |
|------|------|
| 메서드 실행 | 메서드 호출 시점 |
| 생성자 호출 | new 객체 생성 시점 |
| 필드 값 접근 | 필드 읽기/쓰기 시점 |
| static 메서드 접근 | 정적 메서드 호출 |
| 메서드 예외 | 예외 발생 시점 |

**스프링 AOP는 메서드 실행 지점만 가능하다.**

프록시는 메서드 오버라이딩으로 동작하므로:
- 생성자 → 프록시 불가
- static 메서드 → 프록시 불가
- 필드 값 접근 → 프록시 불가

또한 **스프링 컨테이너가 관리하는 빈에만 AOP 적용 가능** (new로 직접 생성한 객체 불가).

## AOP 용어 정리

| 용어 | 정의 |
|------|------|
| **조인 포인트 (Join Point)** | 어드바이스가 적용될 수 있는 위치. 추상적인 개념. 스프링 AOP는 메서드 실행만 |
| **포인트컷 (Pointcut)** | 조인 포인트 중 어드바이스를 적용할 위치를 선별하는 필터. 주로 AspectJ 표현식 |
| **타겟 (Target)** | 어드바이스를 받는 실제 객체. 포인트컷으로 결정됨 |
| **어드바이스 (Advice)** | 부가 기능 로직. Around, Before, After 등 종류가 있음 |
| **애스펙트 (Aspect)** | Advice + Pointcut을 모듈화한 것. @Aspect로 정의 |
| **어드바이저 (Advisor)** | Advice 1개 + Pointcut 1개. 스프링 AOP 전용 용어 |
| **위빙 (Weaving)** | 포인트컷으로 결정한 타겟의 조인 포인트에 어드바이스를 적용하는 것 |
| **AOP 프록시** | AOP 기능을 구현하기 위해 만든 프록시 객체. JDK 동적 프록시 또는 CGLIB |

## stylink 적용 포인트

```
InventoryService.hold()  → @Transactional → 스프링 AOP (런타임 프록시)
OrderService.order()     → @Transactional → 스프링 AOP
PaymentService.pay()     → @Transactional → 스프링 AOP
```

- **조인 포인트**: `hold()`, `order()`, `pay()` 메서드 실행
- **포인트컷**: `@Transactional` 애노테이션이 있는 메서드
- **어드바이스**: 트랜잭션 시작 → 커밋/롤백
- **타겟**: 실제 `InventoryService`, `OrderService` 객체
- **위빙**: 런타임, 프록시 방식

## 면접 Q&A

**Q: AOP란 무엇이고 스프링에서 어떻게 구현하나?**  
A: AOP(Aspect-Oriented Programming)는 로깅, 트랜잭션 같은 횡단 관심사(cross-cutting concerns)를 핵심 비즈니스 로직에서 분리해 한 곳에서 관리하는 프로그래밍 패러다임이다. 스프링 AOP는 런타임에 프록시를 생성해 부가 기능을 적용하는 방식을 사용한다. `@Aspect`, `@Around` 등의 애노테이션으로 Advice와 Pointcut을 정의하면, `AnnotationAwareAspectJAutoProxyCreator`가 자동으로 프록시를 만든다.

**Q: 스프링 AOP가 메서드 실행에만 적용 가능한 이유는?**  
A: 스프링 AOP는 프록시 기반이기 때문이다. 프록시는 메서드 오버라이딩으로 동작하므로 메서드 실행 시점만 가로챌 수 있다. 생성자 호출, static 메서드, 필드 접근은 프록시로 가로챌 수 없다. AspectJ를 사용하면 컴파일 타임이나 클래스 로드 타임에 바이트코드를 조작해 이런 위치에도 AOP를 적용할 수 있지만, 설정이 복잡해진다.

**Q: Join Point와 Pointcut의 차이는?**  
A: Join Point는 AOP를 적용할 수 있는 모든 위치를 추상적으로 나타내는 개념이다. Pointcut은 그 중에서 실제로 어드바이스를 적용할 위치를 선별하는 필터다. 예를 들어 스프링 AOP에서 모든 메서드 실행이 Join Point이고, `execution(* com.stylink.domain..*(..))`처럼 AspectJ 표현식으로 특정 패키지의 메서드만 골라내는 것이 Pointcut이다.

**Q: 위빙(Weaving)이란?**  
A: 포인트컷으로 결정된 타겟의 조인 포인트에 어드바이스를 연결하는 과정이다. 핵심 기능 코드에 변경 없이 부가 기능을 추가하는 것이다. 컴파일 타임(AspectJ 컴파일러), 클래스 로드 타임(바이트코드 조작), 런타임(스프링 AOP 프록시) 3가지 시점에 수행할 수 있다.
